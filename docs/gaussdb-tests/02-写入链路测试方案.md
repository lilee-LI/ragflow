## 概述

本测试方案覆盖 GaussDB DocEngine 的文档 chunk 与文档 metadata 写入、回读、更新、删除全链路，对标技术设计 3.2 节、3.2.6 测试与验收。**第十一组为生命周期集成流程用例**，串联建表→写入→占位→补向量→删除→重建。

**环境标记**：每条用例「类型」带 `· 单元` / `· 集成`：
- `· 单元`：无 DB / mock（DDL builder、纯函数、参数校验、反向错误 mock）；反向错误 mock 仿照真实行为，前置注明 mock 点
- `· 集成`：需 `GAUSSDB_INTEGRATION=1` + 环境指南中 `GAUSSDB_SCHEMA` 指定的 integration schema
- fake/mock 只能形成单元证据；未连接真实 GaussDB、未执行 DB 探针的测试不得标记集成完成

**字段继承**：未单列 Setup/Cleanup 的用例严格继承 [README 的 S/A/A/C 契约](README.md#setup--action--assert--cleanup-继承契约)，不得自行选择其它 fixture 或清理方式。

**测试范围**：
- `create_idx` 建表 / 索引 / 向量列 / DiskANN / advisory lock
- `insert` chunk upsert（行标准化、列对齐、向量判定、mother chunk 占位）
- `insert` doc_meta upsert
- `get` 回读（跨 KB duplicate 检查、占位向量剔除）
- `update`（JSONB 整列覆盖、remove/add、key 列禁止）
- `delete`（id 列表 / doc_id / kb_id / GraphRAG / RAPTOR / must_not exists）
- `delete_idx` / `index_exist`
- `adjust_chunk_pagerank_fea`
- DDL builder 与辅助函数
- 生命周期端到端流程

**涉及文件**：`rag/utils/gaussdb_conn.py`、`common/doc_store/gaussdb_conn_base.py`

**关键方法**：

| 方法 | 签名 | 说明 |
| --- | --- | --- |
| `create_idx` | `(index_name, dataset_id, vector_size, parser_id=None)` | advisory lock + DDL 链 |
| `insert` | `(documents: list[dict], index_name, knowledgebase_id=None) -> list[str]` | chunk / doc_meta upsert；返回错误 id 列表 |
| `get` | `(chunk_id, index_name, knowledgebase_ids) -> dict \| None` | 回读，跨 KB duplicate 检查 |
| `update` | `(condition, new_value, index_name, knowledgebase_id) -> bool` | JSONB 整列覆盖 |
| `delete` | `(condition, index_name, knowledgebase_id) -> int` | 条件删除，返回行数 |
| `delete_idx` | `(index_name, dataset_id)` | 有 dataset_id 清单 KB / 无则 DROP |
| `index_exist` | `(index_name, dataset_id=None) -> bool` | 只读幂等 |
| `adjust_chunk_pagerank_fea` | `(chunk_id, index_name, dataset_id, delta, min_w=0, max_w=100, **kwargs) -> bool` | 原子增减 |

**表名 / 列名约定**：

| 分类 | 约定 |
| --- | --- |
| chunk 表逻辑名 | 任意合法标识符（`index_name`） |
| doc_meta 表 | 必须以 `ragflow_doc_meta_` 开头 |
| 主键 | chunk 表为 `(kb_id, id)`；doc_meta 表为 `id` 主键并建 `kb_id` 普通索引；跨 KB 复用同一 `Document.id` 必须拒绝或跳过 |
| 向量列 | `q_{dim}_vec`（floatvector）+ `q_{dim}_vec_valid`（BOOLEAN DEFAULT FALSE NOT NULL） |
| JSONB 列 | `chunk_data`、`extra`、`metadata`、`important_kwd`、`question_kwd`、`tag_kwd`、`tag_feas`、`position_int`、`page_num_int`、`top_int`、`source_id`、`entities_kwd`、`meta_fields` |
| JSONB 多值列 | `important_kwd`、`question_kwd`、`tag_kwd`、`source_id`、`entities_kwd` |
| 位置排序列 | `page_num_int`、`position_int`、`top_int`（首元素转整数） |
| pagerank 列 | `pagerank_fea`（INTEGER） |
| 默认值 | `available_int=1`、`removed_kwd='N'` |
| GraphRAG 列 | `knowledge_graph_kwd`、`entity_kwd`、`entity_type_kwd`、`from_entity_kwd`、`to_entity_kwd`、`n_hop_with_weight`、`mom_id`、`group_id` |
| RAPTOR 列 | `raptor_kwd`、`raptor_layer_int` |

**事务与错误约定**：
- 所有 DDL / write 在同一事务，失败自动回滚
- `insert` 失败返回错误 id 列表（不抛）
- `update` / `delete` 失败返回 `False` / `0`（不抛）
- DDL 失败抛异常
- 幂等：`CREATE TABLE/INDEX IF NOT EXISTS`；`index_exist` 只读不触发 DDL

**环境连接**：单元层（9xx、部分 0xx/1xx/4xx/5xx/6xx）无需 DB；集成层见 [README 集成测试环境连接](README.md#集成测试环境连接)。

**集成用例公共前置（必须复用）**：
```python
from psycopg2 import sql
from rag.utils.gaussdb_conn import GaussDBConnection

conn = GaussDBConnection()
table = table_name(gaussdb_env, "wrt_xxx")
kb_id = "kb-wrt-xxx"

    return [value] * dim

    conn.create_idx(table, kb_id, dim)

def cleanup_table(admin_conn, schema: str, table: str):
    with admin_conn.cursor() as cur:
        cur.execute(sql.SQL("DROP TABLE IF EXISTS {}.{} CASCADE").format(sql.Identifier(schema), sql.Identifier(table)))
```

- 每个集成用例把 `"wrt_xxx"` 换成当前用例 ID，例如 `table = table_name(gaussdb_env, "wrt_102")`；生命周期用例用 `wrt_1001`、`wrt_1002` 等，不固定共享物理表名。
- schema 来自 `gaussdb_env["schema"]`；表名前缀来自 `gaussdb_env["table_prefix"]`，由 fixture 隔离。
- cleanup 只清理本用例通过 `table_name(gaussdb_env, "wrt_xxx")` 或 `ragflow_doc_meta_{gaussdb_env["table_prefix"]}_wrt_xxx` 创建的对象，不做 `LIKE 'ragflow_%'` 全局清理。
- 集成用例只断真实 DB 状态、返回值和持久化结果；SQL 文本与 params 必须拆到单元用例，用 `RecordingCursor` / `RecordingPool` 断 `cursor.executed`。

  - `(removed_kwd, 'N', character varying)`
