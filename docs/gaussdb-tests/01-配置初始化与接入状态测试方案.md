## 概述

本测试方案覆盖 GaussDB 作为 RAGFlow DocEngine 的配置加载、连接池、schema 解析、settings 初始化、health/status 接入与部署配置渲染。被测代码对应技术设计 3.1 节、3.1.6 测试与验收。

**环境标记**：每条用例「类型」带 `· 单元` / `· 集成`：
- `· 单元`：无 DB / mock，随时跑；反向错误场景 mock 仿照真实行为（异常类型 + 消息 + 返回值），前置注明 mock 点
- `· 集成`：需 `GAUSSDB_INTEGRATION=1` + 环境指南中 `GAUSSDB_SCHEMA` 指定的 integration schema

**字段继承**：未单列 Setup/Cleanup 的用例严格继承 [README 的 S/A/A/C 契约](README.md#setup--action--assert--cleanup-继承契约)，不得自行选择其它 fixture 或清理方式。

**本轮实现状态**：TC-CFG-302、306、309、601、607、612、901、902、903、904 均已有不同主函数；Centralized 与 Distributed 的当前结果只以本文件顶部双环境矩阵及对应固定 JUnit 为准。

**测试范围**：
- 配置数据类 `GaussDBConfig` 与 `load_gaussdb_config` 加载
- schema 解析（默认 `public`、标识符校验、空值归一）
- 必填字段与端口范围校验
- 连接池 `GaussDBConnectionPool`（get/put/close、重试、schema 权限检查）
- 错误分类 `classify_gaussdb_exception`（认证 / 权限 / 连接）
- `settings.py` 引擎选择与 `GaussDBConnection()` 初始化
- `health()` / `get_performance_metrics()` / `get_gaussdb_status()`
- status API 与脱敏
- Docker / Helm 配置渲染
- 真实库冒烟（opt-in）

**涉及文件**：

| 文件 | 职责 |
| --- | --- |
| `common/doc_store/gaussdb_conn_pool.py` | 连接配置、连接池、schema 解析、错误分类 |
| `common/doc_store/gaussdb_conn_base.py` | `GaussDBConnectionBase.health()` / `get_performance_metrics()` |
| `common/settings.py` | `DOC_ENGINE` 分支、`GaussDBConnection()` 实例化 |
| `api/utils/health_utils.py` | `get_gaussdb_status()`、脱敏 |
| `api/apps/restful_apis/system_api.py` | `/system/gaussdb/status`、`/system/healthz` |
| `rag/utils/gaussdb_conn.py` | `GaussDBConnection` adapter（`db_type()` 返回 `gaussdb`） |
| `conf/service_conf.yaml`、`docker/service_conf.yaml.template`、`docker/.env`、`helm/*` | 部署配置 |

**关键类 / 函数**：

| 符号 | 签名 | 说明 |
| --- | --- | --- |
| `GaussDBConfig` | `(host, port, database, user, password, schema="public")` | 连接配置数据类 |
| `load_gaussdb_config` | `(raw: dict \| None) -> GaussDBConfig` | 从 `settings.GAUSSDB` 或传入字典加载 |

| `GaussDBConnectionBase.get_performance_metrics` | `() -> dict` | `SELECT 1` 测延迟 |
| `get_gaussdb_status` | `() -> dict` | 返回 `{status, message:{health, performance}}` |
| `_mask_gaussdb_string` | `(value: str) -> str` | `password=` / `password:` → `***`，不区分大小写 |

**异常层级**：

```
GaussDBError(Exception)
├── InvalidGaussDBConfig(ValueError, GaussDBError)      # 配置缺失/非法
└── GaussDBConnectionError(GaussDBError)                # 连接失败
    ├── GaussDBAuthenticationError                       # 认证失败
    └── GaussDBPermissionError                           # 权限不足
```

| 项 | 来源 | 默认 |
| --- | --- | --- |
| `DOC_ENGINE` | env | `elasticsearch` |
| `gaussdb.host` / `GAUSSDB_HOST` | service_conf / env | — |
| `gaussdb.port` / `GAUSSDB_PORT` | service_conf / env | — |
| `gaussdb.database` / `GAUSSDB_DATABASE` | service_conf / env | `postgres`（模板默认） |
| `gaussdb.user` / `GAUSSDB_USER` | service_conf / env | — |
| `gaussdb.password` / `GAUSSDB_PASSWORD` | service_conf / env | — |
| `gaussdb.schema` / `GAUSSDB_SCHEMA` | service_conf / env | `public` |

GaussDB 配置固定采用平铺结构，不增加 `gaussdb.config` 兼容分支；这样可直接复用 RAGFlow 原有 `show_configs()` 对第一层 `password` 的脱敏行为。其他模块已有的嵌套敏感配置日志问题不属于 GaussDB 适配范围。

**与 OceanBase status 对标差异（必须显式测试）**：

| 特性 | GaussDB | OceanBase |
| --- | --- | --- |
| 兼容模式硬检查 | 强制 `sql_compatibility ∈ {A, ORA}`，否则 unhealthy | 无 |
| 错误脱敏 | 专用 `_mask_gaussdb_string` 递归脱敏 password | 无专用脱敏 |
| 性能指标 | `connection` / `latency_ms` / `schema` | 含 storage/QPS/slow_queries |
| 响应结构 | 嵌套 `{status, message:{health, performance}}` | 扁平 `{status, details}` |
| 延迟阈值 | 无（仅看 `health.status` 字符串） | `latency_ms < 1000` |
| 初始化权限检查 | 构造时 `check_schema_access()`（USAGE+CREATE） | 无强制 |
| 未配置响应 | `{status:"not_configured", message:"GaussDB is not configured"}` | `{status:"not_configured", details:{connection:"not_configured"}}` |
| msgStoreConn | 无 | 有 `OBConnection` |
| schema 概念 | 有，默认 `public` | 无 |

**环境连接**：单元层无需 DB；集成层见 [README 集成测试环境连接](README.md#集成测试环境连接)（`GAUSSDB_INTEGRATION=1` + `GAUSSDB_SCHEMA` 配置值）。

**调用约定（单元层）**：
```python
from common.doc_store.gaussdb_conn_pool import load_gaussdb_config, mask_gaussdb_uri, classify_gaussdb_exception
cfg = load_gaussdb_config({"config":{"host":"h","port":5432,"database":"d","user":"u","password":"p"}})
```

**连接池 / 配置单元公共前置**：
- `common.doc_store.gaussdb_conn_pool` 模块末尾会执行 `GAUSSDB_CONN = GaussDBConnectionPool()`；单元测试只要 import 该模块，就必须先 seed `common.settings.GAUSSDB` 为完整 fake 配置，并 patch `psycopg2.pool.ThreadedConnectionPool` 返回 fake pool，否则导入副作用会尝试创建真实连接池。
- 当前测试通过 `_load_pool_module_without_import_state_leaks()` 从生产文件加载测试专用模块名；加载窗口内临时安装 fake `common.settings` 与 fake driver pool，并在 `finally` 中精确恢复原 `sys.modules` 条目及 `common.settings` 属性。
- 不在模块级使用 `sys.modules.setdefault(...)` 污染其他测试，也不删除或替换进程中可能已存在的 canonical `common.doc_store.gaussdb_conn_pool`。断言异常时使用测试专用模块中加载的源码异常类型：`InvalidGaussDBConfig`、`GaussDBConnectionError`、`GaussDBAuthenticationError`、`GaussDBPermissionError`。

## 三、配置缺失与非法（2xx）

### TC-CFG-201: 缺 host

**类型**：异常 · 单元 · P0

**步骤**：
1. `load_gaussdb_config({"config":{"port":5432,"database":"d","user":"u","password":"p"}})`

**预期结果**：
- 抛 `InvalidGaussDBConfig`
- `"missing gaussdb config field(s): host" in str(exc)`
- 错误信息脱敏（不含其他字段值）

**验收口径**：3.1.6「缺 host/database/user/password 或 port 非法时错误可读且脱敏」

**优先级**：P0

### TC-CFG-202: 缺 port / database / user / password

**类型**：异常 · 单元 · P0

**步骤**：
1. 分别调用 `load_gaussdb_config({"config":{"port":5432,"database":"d","user":"u","password":"p"}})`、`load_gaussdb_config({"config":{"host":"h","database":"d","user":"u","password":"p"}})`、`load_gaussdb_config({"config":{"host":"h","port":5432,"user":"u","password":"p"}})`、`load_gaussdb_config({"config":{"host":"h","port":5432,"database":"d","password":"p"}})`、`load_gaussdb_config({"config":{"host":"h","port":5432,"database":"d","user":"u"}})`

**预期结果**：
- 均抛 `InvalidGaussDBConfig`，`isinstance(exc, InvalidGaussDBConfig)` 为 True
- `"missing gaussdb config field(s): host" in str(exc)`、`"missing gaussdb config field(s): port" in str(exc)`、`"missing gaussdb config field(s): database" in str(exc)`、`"missing gaussdb config field(s): user" in str(exc)`、`"missing gaussdb config field(s): password" in str(exc)`
- `host/database/user/password` 为非字符串或只含空白时按非法字段拒绝；不能先 `str(...)` 后把任意对象或空白值当成有效配置
- 错误信息脱敏（不泄露已提供的字段值）

**验收口径**：3.1.4.2「必填字段缺失时错误可读且脱敏」

**优先级**：P0

### TC-CFG-203: port 越界

**类型**：异常 · 单元 · P0

**步骤**：
1. 分别调用 `load_gaussdb_config({"config":{"host":"h","port":0,"database":"d","user":"u","password":"p"}})`、`load_gaussdb_config({"config":{"host":"h","port":65536,"database":"d","user":"u","password":"p"}})`、`load_gaussdb_config({"config":{"host":"h","port":-1,"database":"d","user":"u","password":"p"}})`
